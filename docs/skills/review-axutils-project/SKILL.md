# axutils 项目审查

先读 [架构契约](../../architecture.md) 和 [开发入口](../../development.md)，结合实际 exports 与源码追踪。按用户指定范围选取以下检查项；全项目审查覆盖全部，局部审查仅沿相关依赖和公共契约扩展。审查请求本身不授权修改被审查代码。

## 检查项

1. **公共契约**：逐项对照 exports、运行时导出快照、类型和文档；确认保留原路径、类身份、默认值、返回结构和错误时机。内部目录不自动成为公共 API。
2. **职责与依赖**：检查拆分是否按独立职责；共享层只收纳真正相同的机制。重点复核 Promise/RxJS 的配置、重试和取消差异，Node/通用存储的值语义，日期 peer 边界。
3. **构建与消费**：从 exports 目标派生入口；检查 ESM/CJS external、UMD 内置依赖及编译辅助代码。真实打包验证全部入口、最小 peer 和 NodeNext 双声明图，不能仅跑源码 typecheck 或 publint。
4. **行为与性能**：保持有价值的原测试，用回归证明缺陷修复；异步测试采用确定的完成信号。性能结论报告输入、环境、重复测量和限制，不用源码行数或单次倍率替代收益。
5. **跨端验证**：真实浏览器覆盖存储、计时器和 HTTP，不能由 Node mock/VM 替代；最低 Node 使用同一份产物验证。根检查覆盖每个发布包。
6. **编辑器与格式**：工具配置和测试文件归属可被编辑器发现的最近 tsconfig；Node 类型不能只由子目录反向 include 提供。按[修改后检查](../../development.md#编辑器与修改后检查)核对格式、排序保序及 lint，确认编辑器与 CLI 配置一致。
7. **文档一致性**：包 README、详细示例、依赖映射和命令与实际入口一致；内部文件移动不应造成用户被引导导入私有路径。

## 验证与重构

验证范围和源码/测试重构顺序遵循[开发文档](../../development.md#验证范围)。全项目审查运行 `pnpm check`；局部审查运行相关检查。不得删除或放宽失败断言来掩盖源码问题。

## 输出

先报告会导致错误结果、发布失败或兼容性破坏的问题，再报告维护性与性能机会。每项提供位置、触发条件、证据、影响和修正方向；区分复现事实与待验证推测。列出实际验证、未执行的矩阵和剩余限制。没有问题时明确说明审查范围。

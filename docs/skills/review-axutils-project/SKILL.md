# axutils 项目审查

按用户范围选择下列检查面，不把规则审查扩展成全部行为验证，也不因查看一个模块启动全仓重构。审查默认交付发现与证据；用户同时要求优化、修复或固定规则时，完成对应范围内的修改和验证。

## 规则与 Skill 审查

- 按[规则分工](../../../AGENTS.md#架构基线与规则维护)核对每个主题的归属：入口是否承担过多细节、包规则是否复制共享规范、Skill 是否重新定义长期约定。保留有用导航，把重复要求改为指向归属文档的链接。
- 比对规则与当前源码、包清单、配置和实际调度；区分通用基线、本包特例和历史故障示例，避免把偶发现象升级为全局要求。只审查当前任务适用的规则与 Skill，项目任务不自动修改宿主全局规则或插件缓存。
- 架构定稿需给出目录职责、新功能落位、文件拆分条件、依赖方向及演进方式；按[架构基线](../../architecture.md)检查是否既能指导新增内容，又保留现有公共契约。
- 修改后检查相对链接与锚点、Skill 元数据和触发描述；必要时用“新增单文件工具、复杂能力拆分、新增包、纯文档修改”等场景核对是否能走到正确规则，不为验证文案增加同文断言。

## 源码与架构审查

1. **公共契约**：逐项对照 exports、运行时导出快照、类型和文档；确认保留原路径、类身份、默认值、返回结构和错误时机。内部目录不自动成为公共 API。
2. **职责与依赖**：按[文件拆分](../../architecture.md#功能落位与文件拆分)和[依赖方向](../../architecture.md#职责与依赖方向)追踪实际调用、运行时导入及类型引用；检查共享层反向依赖、跨包私有引用、平台能力和可选 peer 泄漏。包特有差异查对应 AGENTS，不因代码形似而合并策略。
3. **工具链与消费**：对照[构建契约](../../architecture.md#构建与声明)和[验证层次](../../development.md#验证层次与子包接入)，检查 exports 派生、external、双声明图、tarball 与最小 peer，以及新包是否漏掉某个验证阶段。区分源码检查、mock 与真实浏览器/最低运行时证据。
4. **编码与行为**：按[编码规范](../../coding-standards.md)检查类型边界、错误时机、数据修改、资源释放和文档。源码与测试重构保留原行为基线；性能建议有测量依据，结构建议给出具体职责和依赖收益。
5. **配置与文档**：检查工具配置和测试能被所在 tsconfig 与编辑器发现，格式处理遵循[修改后检查](../../development.md#编辑器与修改后检查)。包 README、示例、依赖映射和命令对应真实入口，内部移动不引导用户导入私有路径。

## 验证与重构

根据[验证范围](../../development.md#验证范围)选择检查，纯规则修改核对内容、链接和元数据；声称发布包集成兼容时需要对应的真实消费证据。检查失败先区分实现、测试假设与环境问题，调整断言需保留原契约及真实缺陷的检测能力。

## 输出

先报告会导致错误结果、发布失败或兼容性破坏的问题，再报告规则差距、维护性与性能机会。每项提供位置、触发条件、证据、影响和修正方向；区分复现事实与待验证推测，不能把风格偏好当成行为错误。说明已落实的修改、可选建议、实际验证和未覆盖范围；没有发现问题时也明确审查范围。

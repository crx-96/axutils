# axutils 项目审查

结合实际 exports 与源码追踪，遇到契约或工具链信息缺口时查[架构契约](../../architecture.md) 和[开发文档](../../development.md) 对应章节。按用户指定范围选择检查项；全项目审查覆盖相关发布包和下列适用维度，局部审查沿证据涉及的依赖与公共契约展开，深度随风险调整。

审查任务默认交付发现与证据；用户已要求修复时，可继续完成范围内的修复和验证。常规取舍与澄清按[项目任务判断](../../../AGENTS.md#任务判断)处理。

## 检查项

1. **公共契约**：逐项对照 exports、运行时导出快照、类型和文档；确认保留原路径、类身份、默认值、返回结构和错误时机。内部目录不自动成为公共 API。
2. **职责与依赖**：检查拆分是否按独立职责；共享层只收纳真正相同的机制。重点复核 Promise/RxJS 的配置、重试和取消差异，Node/通用存储的值语义，日期 peer 边界。
3. **构建与消费**：核对 exports 目标派生入口的机制，检查 ESM/CJS external、UMD 内置依赖及编译辅助代码。发布兼容性结论由真实打包消费证据支持，覆盖审查范围的入口、最小 peer 和 NodeNext 双声明图；源码 typecheck 与 publint 各自提供部分证据。
4. **行为与性能**：保持有价值的原测试，用回归证明缺陷修复；异步测试采用确定的完成信号。性能结论报告输入、环境、重复测量和限制，不用源码行数或单次倍率替代收益。
5. **跨端验证**：浏览器行为结论由真实浏览器验证支持，按涉及的能力覆盖存储、计时器和 HTTP；Node mock/VM 可辅助定位问题。最低 Node 使用同一份产物验证，根检查覆盖每个发布包。
6. **编辑器与格式**：工具配置和测试文件归属可被编辑器发现的最近 tsconfig，Node 类型由所属项目直接提供，留意子目录反向 include 在编辑器中的归属差异。涉及相关修改时，按[修改后检查](../../development.md#编辑器与修改后检查)核对格式、排序保序及 lint，确认编辑器与 CLI 配置一致。
7. **文档一致性**：包 README、详细示例、依赖映射和命令与实际入口一致；内部文件移动不应造成用户被引导导入私有路径。
8. **编码与错误边界**：按[编码与审查规范](../../coding-standards.md)检查类型断言依据、数据修改、注释归属、资源释放和发布清单；区分同步抛错与 Promise/Observable 的错误通道，核对使用文档是否准确说明。区分既有契约缺陷、新规范差距和可选改进，不把工具已允许的风格差异直接判为行为错误。

## 验证与重构

根据[验证范围](../../development.md#验证范围)选择检查并保留源码/测试重构的对照证据。全项目审查通常以 `pnpm check` 支持集成结论；局部审查选择相关检查，已有且与当前状态匹配的结果可复用。失败断言用于定位实现或测试假设的问题，调整预期时以需求和原契约为依据，保留对真实缺陷的检测能力。

## 输出

先报告会导致错误结果、发布失败或兼容性破坏的问题，再报告维护性与性能机会。每项提供位置、触发条件、证据、影响和修正方向；区分复现事实与待验证推测。列出实际验证、未执行的矩阵和剩余限制。没有问题时明确说明审查范围。

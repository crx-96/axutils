# axutils 项目审查与重构

按用户指定范围选择代码、构建消费或规则文档工作面。仅要求审查时交付发现；同时要求修复或重构时落实已确认问题。开始时遵循[项目入口](../../../AGENTS.md)的 personal 必读要求。

## 建立契约与基线

- 从包 exports、独立导出快照、最小 peer 映射和使用文档确认合法入口与兼容承诺；包内特殊行为见对应 AGENTS。
- 按[验证范围](../../development.md#验证范围)建立与任务相称的原测试基线。源码和测试同时重构时，先保留原断言验证实现，再补缺陷回归或整理测试。
- 先区分业务断言、类型/构建错误与环境阻断。测试未加载或浏览器未启动不能计作业务失败，环境处理见[排查指南](../../troubleshooting.md)。

## 代码与结构审查

| 工作面 | 检查重点 |
| --- | --- |
| 公共契约 | 路径、符号、类型、类身份、默认值、返回引用语义和同步/异步错误时机 |
| 职责与依赖 | 按[架构规范](../../architecture.md#功能落位与文件拆分)识别独立修改原因、状态所有权和依赖边界；检查循环依赖、私有路径、Node 或可选 peer 泄漏 |
| 实现行为 | 按[编码规范](../../coding-standards.md)核对输入校验、getter/toJSON 等副作用、取消/重试、资源释放及真实宿主边界 |
| 构建消费 | exports 派生、external、双声明图、真实 tarball、最小 peer、浏览器和最低运行时；新增包不能漏掉必需阶段 |
| 使用说明 | 参数、单位、错误通道、依赖和示例对应真实实现，内部拆分不引导消费者导入私有路径 |

每个拆分说明新单元拥有的职责和真实调用方；保留内聚实现、合并纯透传层也是有效选择，不以行数或目录整齐替代收益。修复先有复现或可追踪证据，新增测试检验公开行为，不能放宽原断言掩盖回归。

## 规则与 Skill 重整

按[规则分工](../../../AGENTS.md#规则分工与演进)分配唯一正文：入口做导航，personal 记已确认项目偏好，工程文档记实际契约，Skill 记任务流程。全局已生效的要求不复制进 personal，工程事实也不伪装成个人偏好。

规则内容以当前源码、配置和实际验证为依据。调整后核对相对链接、锚点、Markdown 代码块、Skill 元数据与触发条件，并用新增单文件工具、复杂能力拆分、新增包、纯文档修改等场景检查路由是否适当。

## 验收与交付

复用仍有效的检查结果，对本次变更及具体证据缺口完成相称验证；跨模块和公共产物变更通常需要完整消费证据。检查最终 diff 的兼容性、必要性、注释准确性及规则一致性。

先说明会造成错误结果、资源问题或发布失败的缺陷及修复，再说明结构调整。提供触发条件、位置、证据、实际验证和未覆盖范围；将已复现缺陷、规范差距和可选建议区分清楚。

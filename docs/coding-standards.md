# 编码与审查规范

本规范适用于 `packages/*` 的 TypeScript 工具库源码、测试，以及根目录和包内的构建验证脚本。工程目标是公共 API 清晰、跨端行为可靠、发布产物可消费；实现选择结合兼容性、数据正确性和维护成本判断。

已有公共契约、局部规则和工具配置优先。以下补充要求用于新增和本次确需修改的内容；旧代码不因规范落地而批量重命名、格式化或重构。审查应区分既有契约缺陷、新增规范差距和可选改进，不能把风格偏好当成行为错误。

## 规则归属

| 主题 | 依据 |
| --- | --- |
| 格式、导入整理、对象排序和 lint | [根 Biome 配置](../biome.jsonc)及[修改后检查](./development.md#编辑器与修改后检查) |
| TypeScript 编译约束 | [共享 tsconfig](../tsconfig.base.json)与文件所属项目的 tsconfig |
| 公共入口、依赖方向、跨端差异和声明产物 | [架构与兼容契约](./architecture.md)及包内 AGENTS.md |

| 环境、验证命令和发布 | [开发与验证](./development.md) |

同一主题在负责它的文档中维护，不在各层复制配置数值或引入第二套格式化工具。工具检查通过只证明覆盖到的规则，不能代替契约和边界审查。

## 类型与输入边界

- 沿用共享配置的 `strict`、`noUncheckedIndexedAccess`、`exactOptionalPropertyTypes` 和 `verbatimModuleSyntax`；不要通过放宽配置消除局部错误。类型引用使用 `import type` / `export type`。
- 公共函数、方法与稳定的跨模块接口明确参数、返回类型及可选字段语义；局部变量和简单内部回调可使用推断。泛型应表达调用关系，不能把 `T` 当成运行时数据已经校验的证据。
- 未知数据和捕获的异常优先使用 `unknown`，在使用前收窄。类型断言、非空断言和双重断言需要可追踪的依据，例如前置校验、平台能力检查或第三方契约；不要用 `any`、`@ts-ignore` 或宽泛断言掩盖错误。
- 对解析结果、宿主对象及调用方可提供的数据，按公开支持范围检查会影响正确性的类型、范围和缺失值。兼容修改保留既有校验顺序和失败时机；通用工具不额外猜测业务 schema。
- `jsonParse<T>`、缓存读取及 HTTP 响应中的泛型只提供静态类型约定。文档需要说明调用方负责确认数据结构；需要真实校验时在调用边界完成，不声称类型断言具有校验能力。
- 数组、对象或选项是否会被修改，返回值是引用还是副本，应与公开文档一致。处理任意对象键时区分自有属性和原型属性，保留已承诺的 getter、枚举顺序、跨 Realm 和共享引用行为。

## 模块、命名与可读性

- 按功能和独立修改原因组织模块，沿用所在目录的命名。新增多词文件一般使用 `kebab-case`，变量与函数使用 `camelCase`，类型与类使用 `PascalCase`；既有公共命名空间和协议字段保留原名。
- 内部共享层只提取有共同语义的机制，不能反向依赖客户端实现。公共转导出门面用于维持入口；内部转发层应有适配、隔离或兼容方面的实际作用。
- 函数同时承担多种独立职责，或数据和状态变化难以追踪时，先按阶段说明意图，再判断是否拆分。行数不作为强制拆分依据。
- 公共方法和关键边界使用中文注释说明意图、单位、限制、返回语义和失败条件；简单代码通过命名表达。JSDoc 放在对应声明之前并独占注释段，不接在上一个方法的结束括号后；修改实现时同步维护注释。
- 使用局部 lint/排序豁免时写明具体原因并限制范围。故意非法的测试输入、第三方固定名称以及有求值顺序的对象属于可说明的例外，不能为通过检查而破坏它们的语义。

## 异常、异步与资源

- 公共 API 分别说明调用阶段同步抛错、Promise rejection、Observable error，以及 `Safe` 方法的默认返回值。文档示例应覆盖实际的失败通道，不将参数校验错误笼统描述为异步请求错误。
- 只有明确承诺降级、探测能力或返回安全默认值的边界才能捕获并消化异常，并解释返回结果。其他错误按所属层的契约传播或转换，保留已有的错误类型、原始原因和状态信息。
- 不因内部复用而统一 Promise 与 RxJS 的执行时机、重试或取消策略。重试次数、是否允许重试非幂等请求、共享初始化与单次调用取消的关系沿用[架构契约](./architecture.md#职责与依赖方向)。
- 定时器、事件监听、订阅、进行中的请求记录和临时目录应有对应的释放路径，覆盖成功、失败及取消。库代码不增加无约定的日志、网络请求或全局状态修改。
- 测试使用确定的完成信号、虚拟时钟或明确的状态等待；涉及真实宿主行为时使用相应浏览器或运行时验证。mock、时钟、环境变量和临时资源在测试结束后恢复，避免相互影响。

## 依赖、发布与使用文档

- 共享开发工具与包级运行时/可选 peer 的归属沿用[开发约定](./development.md#依赖与发布)。源码不能依赖未声明的传递依赖；新增依赖需有当前功能收益，不为一般便利引入整套框架。
- 发布包清单提供与实际产物一致的名称、描述、仓库目录、`license`、兼容范围、入口及文件白名单；`license` 与仓库许可文件保持一致。核对真实 tarball，不能仅凭工作区文件存在推断它已随包发布。
- 新增或变更公共入口时，同步包清单、运行时导出快照、peer 映射、类型消费用例和使用文档；内部文件路径不是消费者的导入路径。具体构建契约见[架构文档](./architecture.md#构建与声明)。
- 使用文档逐项描述真实入口、参数和默认值、返回结果、错误时机、必要依赖及可运行示例。包 README 的仓库文档链接应能在 npm 包外访问；工具通过不能证明文档与实现一致。

## 检查与结论

按[验证范围](./development.md#验证范围)选择检查，不因只改规则而要求重跑无关测试。全项目审查使用现有根 `pnpm check`，最低消费运行时另由 `AXUTILS_TEST_NODE` 验证同一份产物。

| 检查面 | 当前自动化入口 | 仍需人工确认 |
| --- | --- | --- |
| 格式与静态质量 | `pnpm lint` | 豁免理由、注释归属和职责边界 |
| 类型 | `pnpm typecheck`、`pnpm test:consumer` | 断言依据、泛型承诺和运行时校验范围 |
| 公共行为 | `pnpm test`、`pnpm test:dist` | 需求和边界是否被断言覆盖 |
| 构建与发布 | `pnpm test:tooling`、`pnpm build`、`pnpm test:consumer`、`pnpm publint` | 清单信息、依赖归属和文档一致性 |
| 跨端与最低运行时 | `pnpm test:browser`、`pnpm test:runtime`及指定运行时的消费检查 | 实际运行的平台、版本与未覆盖的环境 |

发现项给出规则依据、准确位置、触发条件或复现证据、实际影响和修正方向。优先报告错误结果、兼容性和发布问题，再报告维护性差距；未经验证的推测单独标记。环境权限或工具启动失败应与代码违反规范区分，审查通过也需说明未执行的验证范围。
